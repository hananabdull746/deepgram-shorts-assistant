# ClipCue outcomes

- [ ] **Install and configure on Ubuntu** — The project includes a reproducible Ubuntu installer and systemd service. The installer creates a dedicated service account, persistent data directories, a protected environment file, a Python virtual environment, installs FFmpeg and app dependencies, starts/restarts the service after code updates, and checks `/health` before reporting success. The operator can set the Deepgram API key without committing it.
- [ ] **Upload and transcribe an authorized source video** — An authenticated user can upload a local video file; the app stores it on disk, rejects unsupported/oversized media and sources above the 1080p resource target, and queues a single job. FFmpeg extracts low-bitrate audio on one thread. Deepgram transcription returns timestamped words/utterances that are persisted for reuse. Optional callback mode accepts results only with the per-job secret token; synchronous mode remains available for local/tunnel-only installs.
- [ ] **Review and refine candidate Short moments** — After transcription, ClipCue proposes multiple timestamped highlight windows with transcript excerpts and transparent heuristic scores. An authenticated user can edit title/start/end and render only a chosen segment. The user remains responsible for rights and final publication.
- [ ] **Render and download vertical clips** — The app produces 720×1280 MP4 clips with readable burned captions and downloadable SRT/VTT files, one FFmpeg process at a time. Completed clips can be downloaded behind authentication; the app does not auto-publish.
- [ ] **Secure access and reliable recovery** — Dashboard routes require login and CSRF validation; sessions use configured secret material; user uploads and generated media stay in protected local storage. Job state survives service restarts; completed transcripts are not automatically resubmitted to Deepgram. Tests cover auth, Deepgram responses, callback tokens, scoring, and clip rendering inputs.
- [ ] **Document operation and limitations** — README explains API key setup, optional public HTTPS callback configuration for long transcriptions, installation/update commands, supported media limits, 1 GB resource behavior, Deepgram costs, backup, and manual review requirements.
